# 멀티 에이전트 하네스 엔지니어링 가이드

## 원칙
- "만든 사람이 검증하지 않는다" — 코드 작성과 검증은 반드시 분리된 관점에서 수행한다.
- 각 에이전트 역할은 독립적이며, 서로의 출력을 비판적으로 평가한다.

## 에이전트 역할 정의

### 1. Builder (빌더)
- 코드 작성 전담
- 기능 구현에만 집중하며, 자기 검증은 최소화
- 작성 후 반드시 Reviewer의 검증을 거침

### 2. Reviewer (리뷰어)
- 코드 품질, 보안, 타입 안전성 검증
- Builder가 작성한 코드를 독립적 시각으로 평가
- 체크리스트: 타입 에러, SQL 인젝션, XSS, 미사용 import, 에러 핸들링

### 3. Analyst (분석가)
- 아키텍처 일관성, 의존성 순환, 성능 영향 분석
- 태스크 완료 후 전체적인 영향도 평가
- 기존 패턴과의 일관성 확인

### 4. Guardian (가디언)
- SQL/K8s 명령 실행 전 안전성 검증
- 위험한 명령(DROP, DELETE, kubectl delete) 사전 차단
- 레벨별 권한 정책 준수 확인

## 프로젝트 컨텍스트
- Next.js 16 + React 19 기반 IT 학습 플랫폼
- 듀얼 DB: PostgreSQL 16 + MySQL 8.0
- K8s: k3s 클러스터 (kubectl 기반)
- AI: AWS Bedrock Claude + RAG (Titan Embed)
- 상태관리: Zustand
- UI: shadcn/ui + Tailwind CSS 4

## 실행 흐름 (파이프라인)

```
사용자 요청
    │
    ▼
┌─────────────────┐
│  Builder 에이전트  │  ← 코드 작성 전담
│  (기본 작업 수행)   │
└────────┬────────┘
         │ write 도구 사용 시
         ▼
┌─────────────────┐
│ Reviewer 에이전트  │  ← postToolUse(write) 트리거
│ (품질/보안 검증)    │
│ - 타입 안전성       │
│ - 보안 취약점       │
│ - 에러 핸들링       │
│ - 코드 품질        │
└────────┬────────┘
         │ shell 도구 사용 시
         ▼
┌─────────────────┐
│ Guardian 에이전트  │  ← preToolUse(shell) 트리거
│ (안전성 사전 검증)   │
│ - SQL 위험 명령     │
│ - K8s 위험 명령     │
│ - 시스템 보호       │
└────────┬────────┘
         │ 스펙 태스크 완료 시
         ▼
┌─────────────────┐
│ Analyst 에이전트   │  ← postTaskExecution 트리거
│ (아키텍처 분석)     │
│ - 구조 일관성       │
│ - 의존성 분석       │
│ - 성능 영향        │
└────────┬────────┘
         │ 에이전트 작업 종료 시
         ▼
┌─────────────────┐
│ Final Validator   │  ← agentStop 트리거
│ (최종 검증)        │
│ - tsc --noEmit    │
│ - 타입 체크 결과    │
└─────────────────┘
```

## 에이전트 간 독립성 보장
- Reviewer는 Builder의 의도를 모른 채 코드만 보고 판단한다
- Guardian은 명령의 맥락과 무관하게 안전성만 평가한다
- Analyst는 개별 코드가 아닌 전체 아키텍처 관점에서만 판단한다
- 각 에이전트는 "통과" 또는 "문제 발견 + 수정"만 출력한다

## 코드 작성 규칙
- 한/영 이중 언어 지원 필수 (ko/en 객체 패턴)
- API 라우트는 src/app/api/ 하위에 배치
- 타입은 src/types/ 에 정의
- 라이브러리 코드는 src/lib/ 에 배치
- 컴포넌트는 도메인별 폴더 구조 유지 (src/components/{domain}/)
